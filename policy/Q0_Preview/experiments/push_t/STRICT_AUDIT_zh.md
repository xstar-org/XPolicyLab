## 输入边界

| 路径 | 严格组处理 | 允许保留的信息及来源 |
| --- | --- | --- |
| 任务文本 | 只使用冻结官方 description；不附加评分段落、原任务卡或任务参考 | 官方要求，包括对齐、不抬起、打开夹爪、归位 |
| 原始观测 JSON | 在写盘、生成 manifest、SSH 传输前，移除 `home_check`、`near_home`、归位位置和方向误差；未知顶层或机器人状态字段报错 | 当前机器人状态、记录的初始机器人位姿、计时及执行预算 |
| Python 读取观测 | 读取同一份已清理 JSON；模型显示前再次递归检查禁止字段 | 无单独的未清理工具读取入口 |
| 机器人几何 | 使用新的 `strict_geometry.md` | 固定机器人模型尺寸、坐标系、单位；不含物体或桌面尺寸 |
| 历史经验 | 不复制 `geometry_evidence.md`；新提示不用原操作建议、任务实例、历史探测结果 | 当前 episode 由模型自行生成的 memory |
| 任务参考文件 | 不生成 `task_reference.json`；遇到残留文件或悬空链接停止 | 无 |
| 场景几何 | 严格组禁用固定桌面高度保护及 CuRobo 桌面障碍物 | 机器人自身运动学、自碰撞及双臂避碰；模型可以从观测自行估计平面 |
| 几何计算工具 | 保留投影、三角测量、变换、裁剪的通用数学接口 | 每帧相机内外参及模型自己选择的像素；不返回物体真实位姿 |
| 检查点 | 独立模型根据当前图像检查先前计划的预期结果 | 不调用评分器，不读取 reward 或 success |
| 控制器反馈 | 只描述模型所请求运动的执行、误差和拒绝原因；递归禁止评分/物体真值字段 | 运动到达容差、速度、关节限位属于动作接口，不是任务成功阈值 |
| CLI 原生能力 | 沿用隔离 CLI home、禁用原生 shell/文件/搜索/MCP/子 agent，核对实际工具目录的实现 | 模型只调用 Q0 允许工具；Python 在无网络沙箱中运行 |
| 官方评测结果 | 原生评测器在模型外记录 | 不反馈给模型，不跨 episode 传递经验或结果 |

严格观测过滤入口是 `runtime/strict_information.py`，在
`runtime/episode.py` 发布前执行，在 `harness/runner.py` 接收后复查。
原始两种模式保持原行为，以免静默修改历史基线。

机器人初始位姿是已观测机器人状态，不是预写的物体目标坐标。
600 步预算、25 Hz 和控制器运动约束保留；这些定义执行接口与试验预算。
相机标定、机器人模型、Python 几何工具和运动规划器均为公开披露的额外
控制能力，因此本轮依旧是完整 agent 方案，不能等同于仅用图片的 VLA。
保留相机标定并非自行推定：已核对当前[官方规则第 2 节](https://robodojo-benchmark.com/leaderboard/agent-rule#permitted-information)，
其中明确允许当前局的 RGB、机器人本体状态、相机内外参及动作执行结果，
并允许通用控制能力和通用 harness。此处只说明这些保留项的公开依据，
不将本次同布局消融实验宣称为官方认证成绩。
