# Q0 × gpt-6.2-sol：push_T 额外任务信息消融

完成日期：2026-11-21（北京时间）。两组各 50 局，使用同一批冻结布局 ID 0–49，由 RoboDojo 原生评测器判定。

**2026-11-22 审计更正：旧 `official_only` 组不是彻底去除额外信息的对照。** 全部 50 局的 1,542 份原始观测仍包含默认归位容差 `0.15 m / 20°` 及派生 `near_home`；沙箱还提供历史任务探测经验和固定桌面高度。下列成功数不变，但 90% 只能解释为移除所列 `push_T` 专属阈值及任务参考后的结果。不能以受限参考文件数量为零，推断整个输入流程无额外信息。新增 `strict_official` 模式用于进一步清理及独立重测，未将其结果混入本报告。

**原始组 46/50（92%），去除额外信息组 45/50（90%），相差 2 个百分点。本次样本未检出显著差异；不能据此断言额外信息无效，也不能外推到其他任务。** 两组均使用 Fast 的 21 个配对布局中，两组都是 20/21（95.24%）。

## 实验回答什么问题

保留 Q0 的视觉观察、双臂控制、规划与检查点反馈流程，将推理后端替换为 `gpt-6.2-sol`，比较保留原始额外任务信息与只提供官方任务信息的表现。这是模型替换后的信息消融实验，并非官方 Q0 提交所用模型的数值复现，也不是 OpenWAM 与 Q0 的直接重测。

任务选为标准 `push_T`，机器人 `arx_x5`，seed 为 1，使用 joint 控制。任务要求将 T 形物块推至灰色目标，匹配位置和方向，全程不抬起，最后打开夹爪并双臂归位。评测包含物体与目标布局变化，但这里只测一个任务和一个 seed。

## 推理及评测协议

- 日本 VPS 运行 agent，4090 集群运行仿真与控制，经私有 SSH 通道交换观察与动作。
- 使用订阅认证的 Codex CLI 0.166.0，指定 `gpt-6.2-sol`；正式 CLI 样本没有回退到付费 API。
- 保留 Q0 规划、工具调用、观察反馈及历史传递。CLI 原生文件、Shell、网络、MCP、子 agent 等能力被隔离，只执行允许的 Q0 工具。该适配仍有 Codex 包装提示、动态工具交接等传输差异，不能视为与原 API 完全等同。
- 每局最多 600 个控制步，控制频率 25 Hz，即最多 24 秒控制时间；检查点 60 秒，单局墙钟 10800 秒，单轮 3600 秒，最多 100 个计划。控制时间与模型等待的墙钟时间不同。
- RoboDojo 标准 `push_T` 默认评测数量是 **25**。为满足本次各 50 局要求，冻结快照只把该任务数量从 25 扩为 50，并同步可信计数检查；物理、成功判据、布局与控制预算保持一致。因此本结果是 50 局扩展实验，不能标为官方默认榜单协议结果。
- 原始组先完成的 25 局正常结束后被完整保留，再以经校验的续跑机制扩展至 50 局。真实失败不重跑、不替换；只排除有证据且没有闭合有效结果的基础设施或人工暂停尾局。
- 六局 API 试跑（五成功、一失败）、接口验证和模型预检均不计入这 100 局。

## Fast 模式与配对子集

用户在原始组运行中要求切换 Fast。已启动的局继续使用其启动配置，因此原始组布局 0–28 使用 Standard，29–49 使用 Fast；对照组全部使用 Fast。不能把完整 50 对解释为所有运行条件都相同的严格单变量实验。

另外报告两组都使用 Fast 的布局 29–49，共 21 对；子集规则是已核验的服务模式边界，不按成功结果筛选。统计脚本仍要求先验证两组完整 50 局。

| 组别 | 成功 | 成功率 | Wilson 95% 区间 | 失败布局 ID |
| --- | ---: | ---: | --- | --- |
| original Fast | 20/21 | 95.24% | 77.33%–99.15% | 32 |

该子集两组均成功 19 对、各自单独成功 1 对、共同失败 0 对；成功率差为 0，双侧精确 McNemar **p=1.0**。子集更小，而且仍存在硬件、并发与运行阶段差异，不能消除全部混杂因素。

三次格式错误均为检查点回复未提供唯一 `checkpoint_decision`，按原流程恢复，所属局的真实结果和错误均保留；这些局最终成功，没有因错误而重跑。对照组全部回执均请求 Fast 且收到 `priority` 确认，全部 50 局上下文 SHA256 一致，受限参考文件数为 0。

对照组有效档案来源为 `parallel-official-cli-001` 的前 13 局及 `parallel-official-cli-004` 的后 37 局。中间 `003` 的未闭合尾局因用户要求暂停而中断，按暂停前已验证的 13 局前缀继续；未删除已闭合真实失败。`002` 在投递前资格检查失败，没有产生有效样本。早期基础设施中断、暂停与恢复均保留私有证明和 lineage。

原始组完成后的重复串行对照启动保护退出发生在原始结果已写出之后，不是原始组评测失败。当前恢复段模拟器 worker 返回 0，驱动完成 50 个档案及冻结布局一致性校验后写出最终结果；驱动、通信桥、审计进程正常结束。独占的单 GPU step 自然结束，**没有取消或释放共享 Slurm allocation `1827888`**。

每局墙钟中位数为原始组约 15.93 分钟、对照组约 16.76 分钟。它们包含不同动作步数、模型调用与执行阶段，不能用来推断 Fast 的加速比或额外信息的计算开销。

## 如何理解结果

本次 `push_T` 实验中，去掉额外任务信息后仍有 90% 成功率，完整样本差距为 1 局，Fast 配对子集成功数相同。当前证据支持“移除这些信息后该任务仍能维持较高表现”，不支持“所有任务都不需要额外信息”或“额外信息没有潜在优势”。

模型服务模式、硬件与并发阶段并非完全一致：早期对照与原始组共享 GPU 并行，后续对照独立续跑，人工资源暂停后又迁移到另一分配。加上单任务、单 seed、每组仅 50 局及模型输出随机性，这些限制应与数字一起保留。是否符合官方 agent 规则也不能仅由成功率差异判断，应独立依据所提供的信息和工具审查。
